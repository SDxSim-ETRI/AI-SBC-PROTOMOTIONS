### 확정된 것

1. **헤드라인 −25.4 %는 토크가 아니라 각속도에서 온다.** 교차 대입: τ_B·ω_A = 176.8 W
   (−2 %), τ_A·ω_B = 143.4 W (−21 %). 착용자 토크 RMS는 오히려 +2.9 %.
   근활성 프록시 τ²로 재면 **+7.0 %로 나빠진다.**
2. **다만 보행 과제 자체는 안 깨진다.** 전진 거리·속도 +0.0 %, 몸체 추종 오차
   0.069 → 0.070 m, 주기 1.117 s 동일. 줄어든 건 앞으로 나아가는 데 안 쓰이던
   여분의 고관절 스윙(55.5° → 48.5°)이다.
3. **v10은 유각기에서만 일한다.** 위상 구간별 τ² 기여를 절대값 (N·m)²으로 쪼개면
   (무보조 합계 11,276 → 보조 12,069):

   | | 착지 0~20 % | 유각 30~70 % | 합계 |
   |---|---|---|---|
   | v10 (base) | **+2,188** | −1,344 | **+793** |
   | 0~10 % @ −80 오라클 | −2,709 | +7 | −2,403 |
   | β=0.5 오라클 | −2,331 | −991 | **−3,641** |

   v10은 유각기에서 −1,344를 벌지만(착용자 굴곡 토크 +47 → +2 등, 거의 완전히 대신
   받는다) 착지에서 +2,188을 까먹는다 — 착용자가 신전 토크를 낼 때 보조가 굴곡 +14를
   밀어 착용자 토크가 −71 → −111로 **커지기** 때문이다. β 오라클은 **두 구간 모두**
   벌어서 −3,641에 닿는다.
4. **가설 1(착지에 신전 토크를 밀면 추종이 흔들린다)은 반증됐다.** −40 N·m를 넣어도
   몸체 오차 −0.0 %, −80 N·m에서도 −0.1 %. 착지 구간은 건드리면 안 되는 구간이 아니다.
5. **방향이 전부다.** 같은 창·같은 크기에서 −40 N·m는 τ² −12.5 %, +40 N·m는 +14.8 %
   — 게이트를 켜는 것 자체의 부작용이 아니다. v10(+7.0 %)은 이 둘 중 **반대 부호 쪽에
   가깝다.**
6. **한계 40 N·m는 실제로 병목이다.** 착지 창에서 −40 → −80으로 올리니 τ² −12.5 →
   −21.4 %로 거의 선형으로 좋아지고, 그래도 보행은 안 흔들린다.
7. **상한은 β 오라클이 보여 준다.** τ_보조 = 0.5 × 착용자 토크(±40 clamp)면 τ² −32.3 %,
   **\|ω\| −0.9 %**(동작을 안 바꾸고 얻은 절감), 보조 RMS는 v10보다 **적은** 22.2 N·m.
   보조–착용자 토크 상관 0.86 / 부호 일치 86 % (v10은 0.32 / 64 %).

### 원인

보상이 `−w·|τ_agent·ω|`인데, 착지 순간은 τ가 −200 N·m여도 ω가 작아서(위상 0 근처
0.63 → −0.56 rad/s) 이 식이 매기는 가치가 거의 0이다. 그래서 정책이 착지를 버리고
유각에 토크를 몰았다 — **자기 목적함수 기준으로는 옳은 선택이었다.** 게다가 이 식은
착용자 다리를 덜 흔들게만 해도 점수가 오른다. 정책이 그 해도 같이 찾았다.

### 남은 의문

* τ²는 근활성 프록시일 뿐 대사량이 아니다. \|τ·ω\|와 τ²를 섞은 비용
  (예: τ² + 양의 일)이 더 맞는지는 아직 안 재 봤다.
* β 오라클은 착용자 토크를 알아야 한다 — 실기기에서 못 잰다. 재학습된 정책이
  hip 각도·각속도와 HLP 예측만으로 그 상관 0.86에 얼마나 다가가는지가 관건.
* 착지 직전(90~100 %)은 −80 오라클에서 유일하게 나빠진 구간이다 (τ² +357 (N·m)²,
  착용자 토크 −58 → −64 N·m). 착지 직전에 미리 버티는 몫이 늘어난 것으로 보인다.

## 2-B. v11 실험 — τ² 항 추가 + 토크 한계 해제 (2026-09-16, 중단)

§2의 진단대로 `--human-cost both`(|τ·ω|와 τ²를 반씩)를 넣고 **토크 한계를 사실상 풀어서**
(200 N·m = 착용자 자신의 고관절 피크 토크) 학습했다. run `results/llp_gait_v11`,
epoch 8,020에서 중단.

### 목적함수 변경은 성공했다

걷기 40 s 짝비교(착용자 v32, 무보조 A 대비):

```
run           P|τω|      τ²     |τ|      W+      W−     |ω|  전진속도  몸체오차  보조RMS
base(v10)     -24.7    +7.0    -5.5   -16.6   -41.9   -11.6    +0.0    +1.6     30.8
v11 @1000     -25.8   -32.9   -15.3   -46.2   +16.8    +4.1    +0.1   +27.0    102.8
v11 @2000     -32.2   -55.4   -30.5   -50.8    +7.0   +14.4    +0.1   +20.4     99.9
v11 @8000     -52.1   -80.1   -54.2   -61.7   -31.8    +9.8    +0.1   +21.5     97.8
β 오라클      -20.3   -32.3   -22.4   -15.8   -29.7    -0.9    +0.0    -1.1     22.2
```

epoch 2,000에 이미 **τ² −55.4 %**로 β 오라클을 넘었고 최종(8,000)에는 **−80.1 %**까지 갔다.
**|ω|는 +10~14 %** — 착용자 다리가 **더** 움직이는데 근토크는 1/5로 줄었고 전진 거리는
동일하다. v10의 속도 꼼수는 완전히 사라졌다. 몸체 오차는 +21 %(0.084 m)에서 멈춰
hinge가 그 선은 지켰다.

### 한계를 푸니 달리기가 죽는다

```
달리기(motion 1) 40 s          생존    착용자 파워       보조 RMS
v10 (40 N·m)                  40 s   362 → 307 W       33.5 N·m
v11 @2000 (한계 없음)          2.7 s   325 → 636 W ↑    135.7 N·m
v11 @8000 (최종)              1.95 s                    ← 걷기를 잘할수록 더 빨리 죽는다
```

분업이 학습 내내 **단조롭게 심해졌다** — 걷기 τ² −55 → −80 %로 가는 동안 달리기 생존은
2.7 → 1.95 s로 짧아졌다.

`eval/success_rate`(hip 각도가 mocap에서 평균 28.6° 이상 벗어난 에피소드 비율의 여집합)가
**8,000 epoch 내내 0.70~0.72에서 안 움직였다**(v10은 0.92). 학습 비중이 걷기 0.75 /
달리기 0.25라, 정책은 "걷기에서 크게 벌고 달리기는 버린다"에 고착했다.

**즉 토크 한계는 모터 스펙 문제만이 아니라 착용자 안정성 제약이다.**

### 같이 확인된 두 가지 함정

* **효력 벌점이 몰래 한계 노릇을 한다.** `assist_effort`는 Στ²_assist라 한계의 제곱으로
  커진다. weight를 고정해 두면 200 N·m에서 포화 시 −4.0/step(40 N·m의 25배)이 된다.
  `llp_walk.py`가 이제 (40/한계)²로 자동 환산한다.
* **hinge는 몸체 *평균 위치*만 지키고 hip *궤적*은 전혀 묶지 않는다.** 학습 분포에서
  무보조 몸체 오차가 0.103 m라 margin 0.09는 헐겁지 않지만(오히려 항상 조금 걸려 있다),
  이 가드는 정책이 hip 궤적을 크게 흐트러뜨리는 것을 막지 못한다. v10도 같은 구멍이
  있었고(hip 오차 6.3° → 10.3°) 40 N·m로는 크게 못 벌렸을 뿐이다.

### 왜 걷기는 되고 달리기는 죽는가 — 낙상 trace에서

달리기 40 s 평가(v11 @2000)의 보조 토크는 **±200 N·m 한계에 시간의 69 % 붙어서 부호를
마구 뒤집는다**(RMS 129.5, 착용자 토크와 상관 +0.26). "타이밍은 맞는데 세다"가 아니라
분포 밖에서 진동하는 것이고, 착용자는 그 진동에 흔들려 2.7 s에 쓰러졌다. 걷기에서는 같은
정책이 상관 0.6~0.9대로 제대로 돕는다. 원인 후보 셋:

1. **달리기가 학습의 1/4뿐**(walk 0.75 / run 0.25) — 걷기에서 버는 보상이 압도적이라
   "걷기 극대화 + 달리기 포기"가 더 높은 점수를 받는다.
2. **관측에 보행 종류를 구분할 정보가 없다.** LLP 관측은 설계상 hip-local(각도·각속도·
   히스토리·HLP 창)이다. 40 N·m에서는 반사 하나로 둘 다 안전한데 200 N·m에서는 두
   최적해가 갈라진다. **권한이 커질수록 더 많은 맥락이 필요하다.**
3. **종료를 벌하는 항이 없다 (v10에도 있는 구조적 결함).**
   `ppo/agent.py:287`의 `next_value = value × (1 − terminated)`로 종료 시 가치가 0이
   되는데 step당 보상은 항상 음수다(v10 −0.60, v11 −0.53). γ=0.99면 **계속 가는 가치는
   음수, 끝내는 가치는 0** — 일찍 끝내는 쪽이 이득인 구조다. 다만 에피소드 길이 추세가
   두 run 모두 들쭉날쭉해(v10도 중간에 145까지 떨어짐) 이게 v11 실패의 실제 원인이라고
   단정할 근거는 아직 없다. **생존 보너스를 넣은 대조 실험으로 확인할 것.**

정리하면 **토크 한계는 잘 배운 구간에서는 족쇄지만 못 배운 구간에서는 안전망이었다.**
v10이 달리기에서 40 s를 버틴 것도 달리기를 잘해서가 아니라(상관은 비슷하게 낮다)
40 N·m로는 사람을 넘어뜨릴 수 없어서다.

## 2-D. 진자 단계 재점검 (2026-09-17) — "진자가 본 착용자"와 "보행 착용자"의 차이

사용자 가설: θ_g·τ_agent가 sine에 치우쳐 주기함수에만 맞춘 학습이 아니었나. 코드와 파형으로 확인
(그림 `docs/pendulum_vs_walking_torque.png`).

**학습 구조** (`assist_env.py:148-197`, `assist_target_control.py:198-206`, `assist_pendulum/mlp.py:153-217`):
action → tanh×25 N·m → qfrc 주입 / 착용자 = built-in PD(Kp 300, Kd 15) + 속도 피드포워드가
θ_g 추종 / θ_g = offset + a·sin(2πft+φ) + a₂·sin(4πft+φ₂) (기본파+2차 고조파, 세그먼트별 재샘플·
smoothstep 블렌드·hold 15 %·좌우 비상관 25 %) / 보상 = **추종 exp(−40·err²) w=1** + |τ·ω| w=−0.01 +
effort −2e-5 + action rate −0.005 / 종료 = 오차 1 rad·각속도 25 rad/s. 결과 v3: A 12.2 → B 6.3 W
(−48 %), 추종 오차 0.86° → 0.33°, assist RMS 6 N·m.

**파형 측정 (스트라이드별 FFT, 1~2차 고조파 파워 비율 / 피크÷RMS)**

| | hip 각도 | 착용자 토크 τ_agent | τ 범위·RMS |
|---|---|---|---|
| 진자 학습 env (합성 θ_g) | 99.5 % / 1.5 | **94 %** / **2.95** | [−47, +65] N·m, RMS 22 |
| 보행 착용자 v32 (mocap) | **98.3 %** / 1.5 | **72 %** / **4.28** | [−332, +176] N·m, RMS 78 |

→ **각도는 둘 다 거의 sine이다** (실제 mocap hip 각도의 97 %가 기본파). 가설의 "각도가 더 복잡할 것"은
맞지 않고, **차이는 토크에 있다**: 진자의 τ_agent는 sine을 PD로 거른 매끈한 저차 파형이고, 보행
착용자의 τ_agent는 착지마다 지면반력이 만드는 −300 N·m급 신전 스파이크다. 진자에는 접촉이 없어
이 스파이크가 학습 분포에 **한 번도 없었고**, 관성도 0.42 vs 3.5 kg·m²(8배), 착용자 PD의 ω_n도
26 vs 7.5 rad/s로 다른 플랜트였다. 오라클이 찾은 "착지 구간 방향 오류"가 바로 이 빈 자리다.

**보상은 진자 안에서는 옳았다.** 추종 항이 θ→θ_g를 고정하니 |τ_pd·ω| 최소화 = "보조가 추종을 대신함"
이라 사용자가 말한 목표(목표각이 주어지면 추종 토크를 낸다)를 그대로 학습했고 실제로 그렇게 됐다.
문제는 스켈레톤으로 옮기며 **추종 항의 대응물이 없어**(tracker 착용자에겐 θ_g 의도가 정의되지 않음)
몸체 hinge로 바꿨을 때 |τ·ω|의 "다리를 덜 움직이게 하기" 경로가 열린 것이다(§2).

**진자 RL을 다시 볼 때 바꿀 것** (각도 파형 다양성은 병목이 아니었다):
1. 접촉을 흉내 낸 **충격성 외란 토크**(착지 위상에 −100~−300 N·m 신전 부하) 주입
2. **관성·PD 게인 랜덤화**를 0.4~3.5 kg·m², ω_n 7~26 rad/s까지 넓히기
3. 비용은 τ² 또는 |τ·ω|+τ²(§2-B에서 검증된 조합)

**부수 발견 — 진자 env가 headless로 안 뜨던 회귀 2건 수정**: 09-13 `parse_visuals=not headless`
이후 (a) 진자 XML의 geom이 전부 시각 전용이라 질량 0 → `<inertial>` 명시(MuJoCo 값과 Δ≤5e-8),
(b) shape 0개인 로봇에 `_set_robot_friction_to_terrain`이 실패 → `shape_count==0` 가드.
**아직 열린 것**: `verify_controller`가 자동 탐색 HLP(flexion100, 10 ms·6 knot)와 v3 제어기
(25 ms·7 knot)의 chunk 형식 불일치로 실패 — 09-15 HLP 교체 때부터. `--hlp-checkpoint` 인자가 없다.

## 2-E. 착용자 토크 스파이크의 정체 (2026-09-22) — 사람이 아니라 tracker + 강성 PD의 산물

그림 `docs/landing_torque_zoom.png`. 착용자 hip 토크는 tracker(mimic RL)가 50 ms마다 내는 PD
목표각 θ_target에 built-in PD(Kp 200, Kd 20)가 반응한 값이다: τ = Kp(θ_target−θ) − Kd·θ̇.
토크식을 역산해 θ_target을 복원하면(걷기 base run, hip R, 38 s):

| | 값 |
|---|---|
| P항 Kp(θ_target−θ) RMS / D항 −Kd·θ̇ RMS | **94** / 41 N·m — P항이 지배 |
| \|θ_target − θ\| 평균 / p95 | **20.8° / 51°** (실제 각도 진폭은 31°) — 목표각이 각도가 아니라 **토크 손잡이** |
| 50 ms 갱신 경계에서 \|Δθ_target\| / 경계 밖 | **17.2° / 0.1°**; 50 ms 블록 평균이 τ 분산의 **97 %** 설명 → 계단 |
| 착지 한 tick의 원자료 | θ=35.8°인데 θ_target +35° → **−56°** (91° 점프) → −332 N·m; θ̇ +2.5 → −4.3 rad/s in 20 ms |
| 주기 평균 프로파일 피크 | 신전 −157 N·m @ 1 % (−1.73 N·m/kg), 굴곡 +66 @ 37 % (+0.73 N·m/kg) |
| 스트라이드 개별 피크 | −332 N·m = **3.7 N·m/kg** (문헌 보행 hip 모멘트 피크 ≈ 1 N·m/kg; 착용자 90.7 kg) |
| 각도 급변 \|θ̈\| RMS / 최대 | 실제 **48 / 408** rad/s² vs mocap 19 / 72 — 최대는 위상 0 %, τ −332와 동시 |

**왜 각도 변화 대비 토크가 극심한가 — 세 겹**
1. **토크는 입력, 각도는 관성으로 두 번 적분된 출력.** 게다가 입각기에는 발이 땅에 붙어 hip 토크가
   다리(3.5 kg·m²)가 아니라 **몸 전체(≈70 kg·m² 상당)**를 움직인다 → 300 N·m가 각도를 거의 못 바꾼다.
2. **tracker는 목표각을 토크 손잡이로 쓴다.** 1°의 목표 오프셋 = 3.5 N·m. 착지에서 91°를 점프해
   −320 N·m를 만든다. mocap 몸체 위치만 맞추면 되니 토크 모양엔 아무 제약이 없다.
3. **20 Hz 계단.** 갱신 시점마다 평균 56 N·m씩 점프하고 그 사이는 거의 평평하다.

**각도의 급변은 원인이 아니라 결과다.** 실제 사람 각도(mocap)는 97 %가 기본파로 매끈하다. 실제 각도의
꺾임(408 rad/s²)은 tracker의 슬램 + 지면 접촉이 다리를 붙잡는 순간이다. → θ_g(의도·HLP 예측 대상)에
꺾임을 넣지 말 것. 진자에 외란을 넣으면 *실제 각도*에서 저절로 나타난다.

**평균은 생리학의 1.7배, 개별 스트라이드는 3.7배.** 착용자는 사람보다 세고, 스트라이드마다 bang-bang이다.
τ² 절감은 이 착용자를 상대로 잰 값임을 잊지 말 것. (hip effort_limit 600 = 6.6 N·m/kg.)

**진자에 접촉 물체를 두는 것은 틀린 추상화다.** 골반이 고정된 진자는 지탱할 체중이 없고, 발이 블록에
닿으면 다리만 멈춘다(운동학 구속) — 하중도 입각기도 생기지 않는다. 진짜 착지를 만들려면 움직이는 바닥이
필요하고, 그건 다시 보행 모델이다. 대신 이미 있는 qfrc 주입 경로(`assist_env.py:177`)에 외란 채널을 더한다:
* **위상 고정 하중 모멘트 τ_load(φ)** — 환경(착용자 토크에 미포함). 템플릿 = 위 주기 평균 프로파일
  (착지 +굴곡 외력 → 착용자가 신전으로 버팀), 진폭 0.5~2×(문헌 ±1 N·m/kg × 질량), 위상 지터, 가끔
  빠지거나 커지는 펄스(계단·헛디딤). θ_g가 합성이라 위상은 정확히 안다.
* **위상 의존 착용자 임피던스 Kp(φ), Kd(φ)** — 착용자(포함). 입각기에 굳고 유각기에 풀린다(실제
  관절 강성이 그렇다). 진자 Kp 300으로는 157 N·m를 30° 처져야 버티는데, 입각기 Kp 1500이면 6°.
  "큰 토크, 작은 각도 변화"가 여기서 나온다.
* **착지 충격 댐퍼** — 환경. 착지 위상에 −c·θ̇를 잠깐 걸어 땅이 다리를 붙잡는 속도 꺾임을 만든다.
* 그다음 후보: 수동 무릎을 단 2링크(무릎 굴곡에 따른 관성 변화, 문서의 corr 0.19 원인).

검증은 스켈레톤과 같은 잣대로: `compare_runs.py`의 위상표에서 착지 구간 τ²가 내려가는지.

## 2-L. L5 — 반전 관성을 환경이 대신 냄 (2026-09-29 21:57 시작, unit `aisbc-llp-L5`, run `results/llp_L5_pendulum`)

### L2~L5에서 배운 것 (2026-09-29 밤 정리)

1. **진자 정책의 쓸모는 "하중에 맞서 의도의 토크를 대신 내기"에서 나온다.** 하중을 줄이거나(L3) 환경이 토크를 대신 내거나(L5)
   chunk에서 하중 신호를 감추면(L4) 배울 것이 없어지고 W1 전이도 같이 사라진다. **L1(v4)의 무거운 분포가 지금까지 최선**이다.
2. **bang-bang은 "필요량 > 한계"의 결과**다. 한계 랜덤화(L2)로는 안 바뀌고, 필요량을 낮추면(L3) 포화는 줄지만 이득도 준다.
3. **크기(비례성)는 각도만으로는 못 정한다.** 두 착용자(W0·W1)가 같은 mocap을 따르면 정책 입력이 같다. 착용자 근력은
   관측 밖이라 **전역 배율(assist-scale / 한계)은 착용자·구동기마다 정해 줄 값**이고, 정책은 방향·시점을 맡는다.
   β 오라클(착용자 토크 비례)의 −35/−41은 그 특권 정보 덕이며, 각도만 보는 정책의 상한은 아니다.
4. **유각 말기 브레이크는 걷기에선 착지 준비(90~100 %)로 도움, 달리기에선 손해.** 마스크 진단: 달리기 −24 → −30.
   보행 종류별 시점 차이라 각속도 크기로 구분 가능할 수 있음 — 다음 시도할 것이 있다면 여기(달리기 유각 말기).

**현재 결론: 배포 후보 = L1 + 착용자별 배율 0.5(≈20 N·m) — W1 통합 평가 걷기 −19 / 달리기 −24 %.** L2~L5의 코드
(질량 배율, 한계 랜덤화, 반전 사건, chunk 정박)는 옵션으로 남아 있고 기본값은 v4와 같다.

## 3. 토크 한계 40 N·m의 출처 — 스펙이 아니라 우리가 고른 값

- 진자 단계에서 25 N·m로 시작(내가 "착용 장치 현실 범위"로 가정한 값, 근거 문서 없음).

  무겁고 커지고, 보행을 흔들 위험도 커진다.
- **필요한 것**: 실제 장치의 (1) 피크 토크 (2) 연속 토크 (3) 토크 대역폭[Hz].

**L8 가설**: L6에만 보조·착용자 반대 작용 벌점 추가.
`sum_j max(−tau_agent[j] * tau_assist[j], 0)` × **−1e-4**, 항 하한 −3.
관절별 relu 후 합산해 반대쪽 다리의 이득으로 상쇄되지 않게 한다. 동일 물리 창 계측값을 사용.
착용자 토크는 reward에만 사용하며 actor 관측/모델 구조/플랜트/스케일/기존 보상은 L6 그대로.
phase 규칙·추론 gain은 추가하지 않는다. 이 항은 협응 대리지표이며 올바른 일시적 반대 작용까지
억제할 수 있어 성공을 보장하지 않는다. 실제 무보조 대비 부담 증가는 별도 A/B 평가로 검증해야 한다.

### 다음 작업 후보 — 아직 구현·검사·학습하지 않음

L12 파일·서비스·학습은 **없다**. 다음 가설은 추종 보상을 무보조 기준의 비악화 조건으로
바꾸어, 착용자의 원래 움직임을 더 강하게 수정하는 것만으로 보상을 얻는 유인을 줄이는 것이다.
후보 식: `exp(-40 * mean_j(relu((q_B-g)^2 - (q_A-g)^2)))`.
동일한 플랜트·의도·외란·FF종류를 가진 별도 무보조 진자A와 보조진자B를 실제 함께 적분해야 한다.
같은 B상태에서 보조만 빼서 계산한 토크를 A의 반사실적 결과라고 부르면 안 된다.
한 관절의 개선으로 다른 관절의 악화를 상쇄하지 않도록 관절별 hinge를 사용한다.

검토한 구현 방향은 별도 `PairedAssistEnv(AssistEnv)`가 무보조 AssistEnv를 소유하고,
reward 전용 `AssistContext.reference_dof_pos`로 A상태를 전달하는 방식이다.
actor/critic 입력과 추론은 그대로이며, L11의 FF혼합·나머지 보상을 유지해 추종 보상 한 가설만 비교한다.
새 부담-regret 항을 함께 추가하는 것은 별도 가설이므로 이번 변경에 묶지 않는다.

CLI에서 재개할 때 먼저 관련 설계 문서를 읽고 다음을 검증할 것:
1. 두 env의 초기화·step·부분리셋에 같은 난수가 전달되어 플랜트/목표/외란/FF종류가 일치하는지.
   생성자·lazy init도 난수를 사용한다. 보조가 달라도 외생 입력 일치를 직접 검사한다.
2. 양쪽 보조0일 때 상태·토크·추종 보상 일치, A의 보조 정확히0, 모델 관측에 A정보가 새지 않는지.
3. A만 먼저 종료할 때 양쪽 reset 및 truncation/부트스트랩 처리, B실패 flag 보존.
   공통 생존구간의 선택 편향을 기록한다. agent의 episode length 설정도 두 env에 맞춘다.
4. 보상 단조성·관절별 상쇄 금지·유한 gradient, 소규모 PPO 실제 실행, 전체4096env 메모리/속도.
5. GPU 여유·기존 실행 종료 확인 후 새 순차 서비스 하나를 시작하고 epoch 진행을 검증한다.
   L11 완료 결과를 재학습하지 않는다. 기존 전수 결과를 다음 비교 파일로 이어받는다.

이 방향은 잠정 설계이며 성능 개선을 보장하지 않는다. 현재는 사용자가 중지를 요청해 여기서 멈춘다.
미커밋 변경과 모든 원본은 보존했으며 새 커밋은 만들지 않았다. 앱 자동화를 임의로 다시 켜지 말 것.

표준화는 train에서만. 입력은 측정 hip 각도/각속도뿐(시각·phase·참조·토크·접촉 없음).

그 구간에서 힘을 풀어야 함을 배울 기회가 있는 것은 별개다. 이 설명은 아직 물리 원인 가설이다.
다음에는 W1 전신 상태/접촉/착용자 목표·토크를 진단용으로 계측하고, 국소 관측이 유사하지만
요구 토크가 달라지는 조건을 확인할 것. 학습 플랜트와 창 길이를 한 번에 바꾸지 말 것.

### §2-X. 새 대화에서 진행할 느린 걷기 원인 점검

**상태:** 아래 순서는 대화에서 제안했다. 새 학습과 새 출력 비교는 아직 실행하지 않았다.

기존 걷기 학습과 모든 예정 평가는 완료했다. 인계 준비 시 실행 중인 `aisbc-*` 서비스는 없었다.

**목적:** 느린 걷기의 실패가 학습 과정 때문인지, 현재 입력 정보의 한계 때문인지 구분한다.
전체 평균 토크 감소만으로 성공을 판정하지 않는다. 달리기와 다른 동작의 학습은 이후 단계다.

1. **모델을 바꾸지 않고 학습과 평가의 출력 차이를 확인한다.**
   학습은 모델 출력에 무작위 변동을 넣는다. 평가는 평균 출력을 사용한다.
   같은 느린 걷기 조건에서 두 방식을 비교한다. 보상 계산, 학습 때 행동을 평가하는 값,
   관측값의 정규화, 가중치 갱신 계산도 확인한다.
   구현상 불일치가 있으면 추가학습 전에 수정하고 검증한다.
2. **위 점검 뒤 느린 걷기만 짧게 추가학습한다.**
   시작 후보는 부담 비율 반영 400회 모델이다.
   예측기, 보조 모델의 입력, 비교할 보상 계산식을 유지하고 학습 속도를 0.90배로 제한한다.
   제안한 한도는 학습 반복 100회다. 50회와 100회에 평가한다.
   사용할 보상 설정과 초기화 상태는 실행 전에 기록한다. 점검에서 필요한 수정이 드러나면
   수정 이유와 설정 차이를 먼저 남긴다. 보상과 입력을 동시에 바꾸는 실험은 피한다.
3. **결과에 따라 다음 변경을 고른다.**
   느린 걷기만 학습하면 해결되는 경우에는 여러 속도를 함께 학습할 때 생기는 간섭을 확인한다.

   그런 증거가 나오면 몸통 자세와 움직임 등 실제 센서로 얻을 수 있는 입력을 검토한다.
   짧은 추가학습 한 번의 실패만으로 입력 정보가 부족하다고 단정하지 않는다.

### 기존 평가의 정확한 뜻

### 무보조 W1 실제 평가

`evaluate_native_wearer.py`로 고정 W1, 보조 토크 0, 물리 400 Hz/정책 20 Hz, seed 42를 사용했다.
각 조건에서 동일 초기 상태를 둔 복제 환경 두 개를 함께 실행했다. 독립 시드나 독립 사람이 아니다.
원본 시작 시각은 0/0.75초, 최대 길이는 8초이며 클립 끝 0.1초 전에 종료한다.
어느 환경이든 골반 높이 0.5 m 미만이 0.5초 지속되면 낙상으로 기록한다.
몸체 오차는 실행 후 0.5초부터 28몸체의 월드 위치 오차를 평균한다.
낙상 과정의 표본도 포함하며 조건마다 기록 길이가 다르다.

- 먼저 이전 결과 폴더의 `w1_first_probe/`에서 A443 보통/느림을 실행했다.
  2.30/2.10초에 낙상했고 실제 trace/summary가 생성됐다. GPU 실행은 정상 종료했다.
- `w1_existing_walk/`: 기존 gait motion 0, 시작 0/0.75초 모두 8초 유지.
  몸체 평균 오차 약 61.98/64.00 mm, 고관절 RMSE 약 3.48/3.54°, 골반 최저 높이 0.896/0.887 m.
- `w1_native_pairs/`: 느림·보통 8클립×2시작=16조건. 15조건은 1.35–3.10초에 낙상.
  A445 보통/0.75초만 raw 상태가 `clip_window_complete`이지만 마지막 골반 높이가 0.129/0.124 m,
  종료 전 0.45초 동안 0.5 m 미만이었다. 낙상 확인 시간 직전에 클립이 끝나 성공이 아니다.
  원본 raw는 유지하고 `validation_summary.json`에서 `clip_end_low_pelvis`로 분류했다.
- `w1_fast_candidates/`: 3후보×2시작=6조건 중 5조건 낙상.
  A006: 1.55/1.65초, A005: 1.90/2.45초, A417: 3.25초 낙상/3.15초 구간 종료.
  A417/0.75초는 몸체 평균 오차 198/201 mm, 고관절 RMSE 약 9.8°, 종료 골반 높이 약 0.80 m.

### 참조 표현의 영향 — 같은 동작, 같은 실제 초기 상태

기존 걷기의 처음 400프레임을 복사한 4조건을 `make_reference_ablation.py`로 만들었다.
root 위치·회전·선속도·각속도, 모든 관절각·관절속도, 접촉 표식, 40 Hz 시간 간격은 원본과 정확히 같다.
비root 몸체의 위치·회전·속도만 아래처럼 교체했다. 바뀐 값은 같은 root와 관절각으로 계산한
suit FK 및 1프레임 차분 속도다. 기존 데이터/모델은 변경하지 않은 진단용 파생 파일이다.

| 참조에서 교체한 값 | 시작 0초 | 시작 0.75초 |
|---|---|---|
| 없음 | 8초 유지 | 8초 유지 |
| 회전·각속도 | 2.30초 낙상 | 2.65초 낙상 |
| 위치·선속도 | 1.75초 낙상 | 2.40초 낙상 |
| 위치·회전·두 속도 | 1.35초 낙상 | 1.45초 낙상 |

`w1_reference_ablation/`에 8조건을 완료했다. 실제 simulator의 초기 몸체 위치·회전·선속도·각속도와
관절각·관절속도를 기록해 원본 조건과 대조했고, 6비교 모두 최대 배열 차이가 0이었다.
`ablation_reset_verification.json`에 보존했다. 참조에서 채우는 초기 관측 이력은 함께 바뀌므로
미래 참조 하나만 바꾼 실험이라고 쓰지 않는다.

**기존 W1은 기존 참조 표현에 의존한다.** 새 모션 종류나 속도가 없어도 참조 표현을 바꾸면 낙상한다.
새 실제 보행을 현재 W1에 그대로 연결해 LLP 문제로 판정하면 안 된다.
새 변환본의 발 접촉 등 다른 원인을 배제하거나 유일한 원인을 확정한 것은 아니다.

`probe_reference_frames.py`로 기존 걷기의 처음 100초 800표본에 몸체별 고정 회전/이동 오프셋을 맞췄다.
오른발 회전 잔여 RMS 36.8°, 위치 오프셋 잔여 RMS 약 97 mm로 단순 고정 오프셋으로 설명되지 않는다.
결과는 `reference_frame_offsets.json`이다. 임의의 고정 회전 보정으로 호환된다고 가정하지 말 것.
